# AI Talent Copilot 产品案例

## 一句话定位

AI Talent Copilot 是面向企业HR和招聘顾问的招聘辅助工作台，将职位分析、简历解析、人职匹配、面试准备和漏斗复盘连接成一条可解释、可复核的工作流。

它不替HR做录用或淘汰决定，而是帮助HR更快整理信息、发现证据缺口并统一面试准备质量。

## 项目为什么成立

开发者拥有2年以上企业HR经验，支持过销售、市场商务和技术服务三个业务部门，累计招聘13人，并使用Excel搭建过招聘漏斗表和HC管理表。实际工作中反复遇到四类问题：

1. 职位需求依赖个人经验，难以形成统一能力画像；
2. 简历信息密度高，筛选耗时且容易漏掉关键证据；
3. 面试问题缺少针对性，不同面试官的评价口径不一致；
4. 招聘数据分散，只能看到人数，难以及时定位流程问题。

因此，本项目不是“为使用AI而使用AI”，而是把真实招聘工作中的隐性经验转化为可重复的产品流程。

## 核心用户流程

```text
输入职位JD
   ↓
确认职位能力画像、必须条件与信息缺口
   ↓
上传简历、选择是否匿名并提取结构化经历
   ↓
生成分维度匹配评分、优势、风险与原文证据
   ↓
生成STAR问题、追问路径和评价模板
   ↓
由HR填写流程状态与复核结论
   ↓
通过招聘漏斗定位最低转化环节并验证原因
```

## AI与确定性程序如何分工

| 任务 | AI负责 | 程序负责 |
| --- | --- | --- |
| JD分析 | 归纳能力、关键词、信息缺口 | JSON结构校验、字段范围约束 |
| 简历解析 | 抽取姓名、职位、年限、技能、成果 | 文件解析、联系方式脱敏、可选匿名显示 |
| 人职匹配 | 结合证据给出分维度分析 | 匹配等级阈值、展示文案、状态不自动变更 |
| 面试助手 | 生成STAR问题与追问 | 评价表结构、打印/PDF版式 |
| 招聘漏斗 | 补充原因假设与行动建议 | 转化率、最低转化环节、人数合法性校验 |

这套分工的重点是：可以计算和验证的内容交给程序，开放性归纳交给模型，最终业务决策交给HR。

## 关键产品决策

### 1. 证据优先于单一分数

匹配报告不仅展示百分比，还要求模型引用简历原文。HR可以检查结论是否有依据，而不是把模型评分当作黑箱答案。

### 2. “未提及”不等于“不具备”

系统将信息缺失单独列为待验证项，避免因为简历写法差异直接推断候选人能力不足。

### 3. 分数与建议由确定性规则对齐

只有80分及以上显示“建议进入面试”。低分不会因为模型文案漂移而出现“匹配度较高”的矛盾结论。

### 4. 候选人身份可管理，敏感数据最小化访问

为方便候选人管理，简历解析默认保留姓名，同时提供可选匿名化开关。手机号、邮箱和身份证号始终在模型调用前进行基础脱敏。只有HR主动保存候选人时，原始简历和招聘必需的电话、邮箱才进入本地数据库；详情页默认遮罩，查看与下载都会留下审计记录，简历正文不写入localStorage或单独持久化。

### 5. 模型可替换

业务服务只依赖统一的LLM Provider接口，已经验证Mock与DeepSeek OpenAI-compatible链路，可以继续扩展其他模型。

## 技术取舍

- Next.js全栈结构减少MVP部署复杂度；
- SQLite适合本地演示和单实例Docker，正式多用户环境应迁移PostgreSQL；
- Zod用于约束模型结构化输出，同时增加常见包装和类型偏差兼容；
- 浏览器打印用于MVP导出PDF，后续可替换为服务端模板与审计水印；
- 招聘漏斗先使用可解释规则确定瓶颈，再由模型补充待验证假设。

## 如何衡量价值

当前版本是作品集MVP，尚未声称已经产生真实业务收益。进入试用阶段后建议跟踪：

- 单个JD结构化整理耗时；
- 单份简历初筛与证据整理耗时；
- 面试问题准备耗时；
- 匹配结论的证据覆盖率与HR修正率；
- 面试评价完整率；
- 各招聘环节转化率及候选人退出原因完整率。
